# Local Workspace Guide

This guide is for normal manual development in the current checkout. For exact emulator commits, patches and output mappings, see `LOCAL_BUILD_MAP.md`.

## Normal Files I Edit

- `frontend/src/`: React application code.
- `backend/app/`: FastAPI application code.
- `backend/tests/` and frontend `*.test.js`: tests.
- `scripts/`: project maintenance/build/deployment scripts.
- `docs/` and root `*.md`: project documentation.
- `.env.example`, `docker-compose*.yml`, `frontend/package.json`, `frontend/vite.config.js`, `backend/requirements.txt`: versioned configuration when deliberately changing setup.
- `frontend/public/<system>/launcher.*`: product-owned emulator bridge code, but only when working on that emulator integration.

Use `git ls-files <path>` when unsure whether a file is part of the product repository.

## Files I Normally Should Not Edit

- `frontend/dist/`: generated by Vite. It is deliberately untracked.
- `frontend/node_modules/`: installed dependencies.
- `backend/app/**/__pycache__/` and `*.pyc`: Python cache files.
- Most binary/minified/WASM/data files under `frontend/public/`: required runtime assets, usually copied from a third-party build.
- Root third-party repositories such as `EmulatorJS/`, `vAmigaWeb/`, `vice.js/`, `wasm-genplus/`, and `zpz/` unless deliberately building/debugging that emulator.
- `.env`: local secrets.
- SQLite files, `library_media/`, `keropi/config`, and `keropi/sram.dat`: local input/cache/runtime state.

## Emulator Build Source

- C64: `vice.js/`; `scripts/build-vice-wasm.ps1` builds `vice.js/.wasm`, but the deployed files are named `c64.js/.wasm`, so review the undocumented rename/copy step in `LOCAL_BUILD_MAP.md`.
- Amiga PUAE/AGA: `puae-wasm-build/`; build with `scripts/build-puae-wasm.ps1`.
- Amiga vAmiga: `vAmigaWeb/`; current output is in `vAmigaWeb/build/`.
- Mega Drive/Master System: `wasm-genplus/`.
- CPC experimental zpz: `zpz/` plus its `chips` submodule.
- MAME/EmulatorJS: `EmulatorJS/`, `MameWasm/`, `mamejs/` serve different experiments/build layers.
- PC Engine: `beetle-pce-fast-libretro/`.
- Dreamcast experiment: `flycast-wasm/`.
- C64 alternative experiment: `vice32.js/`.
- MAME score definitions: `hi2txt-xml/` upstream checkout; runtime copy is `backend/app/data/hi2txt-xml/`.
- NES verification artifacts: `fceumm-verify/` and root `fceumm-wasm-patched.data`; generating source is not currently documented.

Do not assume a clean upstream checkout is the source of a production binary. Check `LOCAL_BUILD_MAP.md` first.

## Generated Output

- `frontend/dist/`: complete Vite deployment output, recreated with `npm run build`.
- `frontend/public/`: versioned runtime source assets. Emulator builds intentionally copy selected outputs here; changes here may need committing.
- `puae-wasm-build/compile/`: PUAE and RetroArch source/build workspace.
- `vice.js/vice-2.4/`: untracked patched/configured VICE source and object output.
- `vAmigaWeb/build/`: vAmiga output.
- `wasm-genplus/src/main/js/genplus.{js,wasm}`: locally modified build output that exactly matches production.
- `zpz/.zig-cache*`, `.zig-global-cache*`, `zig-out/`: Zig build caches/outputs. One caps-fix cache contains the exact production WASM, so do not bulk-delete them yet.
- `flycast-wasm/pkg-local/`: experimental Flycast output.
- `backend/app/**/__pycache__/`: disposable Python cache, ignored.
- `amstrad_controls/`: ignored generated controller profiles; provenance is not yet captured.

## Git

A normal clean `git status --short` should show nothing. Ignored third-party repositories, build trees, databases, caches and mutable emulator state should not appear.

`frontend/public/` is different from `frontend/dist/`: public is versioned runtime input; dist is generated output. If an emulator build intentionally updates a production runtime, expect only the relevant `frontend/public/<system>/` files plus any build script/documentation changes in the main status.

To see ignored material deliberately:

```powershell
git status --short --ignored
```

To inspect a nested emulator repository, always address it explicitly:

```powershell
git -C wasm-genplus status --short
git -C vAmigaWeb diff
```

The main repository does not report modifications inside ignored nested repositories.

## Adding Normal Website Changes

Edit `frontend/src/`, `backend/app/`, tests or documentation. Avoid opening/saving generated or third-party binary files. Run appropriate tests, then stage explicit paths only.

Example:

```powershell
git status --short
git diff -- frontend/src/pages/LobbyPage.jsx
git add frontend/src/pages/LobbyPage.jsx
git diff --cached
git commit -m "Describe the website change"
```

Never use `git add .` in this workspace.

## Building an Emulator

Before building:

```powershell
git status --short
git -C <source-directory> status --short
```

Record the source commit and existing dirty files before running the build. Use the documented project script when available. Afterward, inspect both repositories:

```powershell
git -C <source-directory> status --short
git status --short
```

Expected main-repository changes should be limited to the intended `frontend/public/<system>/` runtime files and any deliberate launcher/build-document updates. `frontend/dist/` should remain invisible because it is ignored.

## Cleaning After a Build

Start with inspection; these commands do not delete anything:

```powershell
git status --short
git status --short --ignored
git -C <source-directory> status --short
git -C <source-directory> clean -ndX
```

`git clean -ndX` is preview-only: it lists ignored files that would be removed, without removing them. Do not change `-n` to `-f` in `vice.js`, `zpz`, `vAmigaWeb`, `wasm-genplus`, `EmulatorJS`, or `flycast-wasm` until unique work listed in `LOCAL_BUILD_MAP.md` has been committed/exported and the preview has been reviewed.

To recreate frontend deployment output safely, simply run:

```powershell
Set-Location frontend
npm run build
Set-Location ..
```

There is normally no reason to delete `frontend/dist`; Vite updates it and the deployment script rebuilds it. This project currently sets `emptyOutDir: false` to retain legacy fingerprinted CSS URLs.

Python bytecode needs no manual cleanup because it is ignored. If local cache removal is ever necessary, close running Python processes, enumerate exact `__pycache__` targets first, and remove only those directories—not the backend tree.

## Before Committing

1. Run `git status --short`.
2. Confirm only intended product files are visible.
3. If an emulator was built, inspect its nested repository separately.
4. Do not stage `frontend/dist`, nested source trees, databases, firmware experiments or caches.
5. Run relevant tests and the frontend build when frontend behavior changed.
6. Stage explicit files: `git add path/to/file`.
7. Review `git diff --cached`.
8. Confirm no `.env` value, ROM, mutable SRAM/config or unintended binary is staged.
9. Commit with a focused message.

## Recovery and Preservation

No third-party repository was moved or deleted in the workspace cleanup. Their `.git` histories and local modifications remain in the original directories. Preservation-critical trees are `vice.js/`, `wasm-genplus/`, `vAmigaWeb/`, `zpz/`, `EmulatorJS/`, and `flycast-wasm/`; also preserve the patched NES data until provenance is known.

The next preservation step should be per-repository patch export or local commits/branches, stored outside ignored build output and backed up. Do this one emulator at a time after reviewing its diff; do not normalize or reset all repositories together.
