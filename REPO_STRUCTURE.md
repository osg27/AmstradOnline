# Repository Structure

## Tracked product code

```text
backend/
  app/
    api/routes/       FastAPI REST route modules
    core/             settings, database, auth primitives, email, startup migrations
    data/             score parser data, tournament metadata, VIP catalogues, hi2txt XML
    highscores/       game-specific Amiga score extraction
    models/           SQLAlchemy table declarations
    schemas/          Pydantic request/response types
    services/         MAME and Amiga score extraction services
    websockets/       in-memory signaling relay
  tests/              pytest score-extraction tests
  requirements.txt    pinned runtime dependencies (pytest is not declared)

frontend/
  assets/             logos imported by the React bundle
  public/             copied/vendored emulator runtimes, launchers, WASM/data and catalogues
  src/
    api/              fetch wrapper and score client
    components/       reusable social, chat, controller, score and brand UI
    data/             title maps, overrides and controller profiles
    features/         Amiga and local-library domain modules
    hooks/            signaling hook
    pages/            route-level UI; RoomPage and LocalLibraryPage contain most orchestration
    utils/            WebRTC, OCR, notifications and controller helpers
  package.json        Vite/Vitest scripts and JS dependencies
  vite.config.js      build/test configuration

scripts/              deployment, catalogue imports, emulator builds and score maintenance
docs/                 design/investigation notes; currently Amiga auto-configuration plan
keropi/               tracked X68000 firmware/config assets; also contains local untracked runtime state
```

## Root configuration and data

- `README.md`: original foundation/run notes plus MAME high-score operations; parts are stale compared with current features.
- `.env.example`: environment variable template without intended secrets.
- `.env`: local secret-bearing configuration; ignored and must never be committed.
- `.gitignore`: ignores dependencies, local emulator source/build trees, media cache, databases, bytecode and build output.
- `docker-compose.yml`: PostgreSQL, FastAPI/Uvicorn and Vite development services.
- `docker-compose.local.yml`: local port/origin overrides; despite its name it contains a hard-coded admin username and is tracked.
- `cgrom.dat`, `iplrom.dat`: tracked X68000 firmware duplicates also present under `keropi/`.

## Local-only or upstream work trees

The following top-level directories are ignored/untracked build or upstream source workspaces, not part of the tracked product snapshot: `EmulatorJS/`, `MameWasm/`, `mamejs/`, `vAmigaWeb/`, `vice.js/`, `vice32.js/`, `flycast-wasm/`, `wasm-genplus/`, `zpz/`, `beetle-pce-fast-libretro/`, `fceumm-verify/`, `puae-wasm-build/`, `amstrad_controls/`, and `hi2txt-xml/` (currently untracked but not ignored as a directory).

These are confusing because production assets derived from several of them live in `frontend/public/`, while their source history and exact build provenance are not uniformly documented. Keep them out of routine commits and document reproducible update procedures before replacing emulator assets.

## Generated and misplaced material

- `frontend/dist/` is generated by `npm run build` and ignored. The 2026-08-17 workspace cleanup removed its legacy files from the Git index while preserving the local build directory; deployment rebuilds it.
- Generated `backend/app/**/__pycache__/*.pyc` files were likewise removed from the Git index and remain ignored.
- `backend/app/data/hi2txt-xml/` contains thousands of upstream XML definitions in the application package; this is intentional runtime data but would be clearer as a versioned third-party data subtree with provenance/version metadata.
- `RoomPage.jsx` and `LocalLibraryPage.jsx` are very large mixed-responsibility files. Moving pieces is not a low-risk cleanup and should be done incrementally with characterization tests.
- Root firmware/SQLite files are local build/import inputs. SQLite files are ignored; firmware licensing and duplication need investigation before relocation or deletion.
